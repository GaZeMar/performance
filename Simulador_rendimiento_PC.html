Cómo interpretar la simulación

Este laboratorio usa un modelo determinista y simplificado. Cada tarea se divide en cálculo de CPU, espera de memoria, E/S, trabajo gráfico y paginación. Los tiempos de estas fases se suman: T = TCPU + Tmem + TE/S + TGPU + Tpaginación. En una computadora real pueden solaparse y compartir recursos. Las cifras de los escenarios y perfiles son supuestos didácticos, no resultados comerciales.

CPU, núcleos y ley de Amdahl

TCPU = 100·c·L·(3.2/fef)·(1/IPCrel)·(1+b/100)·[(1−P)+P/n]. c es la fracción base de CPU, L el tamaño de tarea, fef la frecuencia efectiva, b la carga de fondo y n el mínimo entre núcleos disponibles e hilos útiles del escenario. fef = GHz·(1−limitación/100). La limitación térmica se impone manualmente; no se calcula a partir de una temperatura física.

P es la fracción paralelizable de la fase de CPU, no de toda la tarea. La parte secuencial no se reparte. Este modelo ideal ignora el costo de sincronización y evita prometer que duplicar núcleos duplique el rendimiento global. Referencia: Amdahl (1967).

Caché, memoria RAM y almacenamiento

La caché reduce una tasa de fallo estimada: m(C)=0.01+0.24·W/(W+C), donde W es el conjunto de trabajo sensible a caché (MB) y C la capacidad de caché efectiva (MB). Tmem = 100·m_base·L·[m(C)/m(8)]·(25/BWram). El denominador m(8) utiliza la misma tarea y tamaño. Es un proxy educativo del costo de fallos, no una implementación de todos los niveles de caché.

La RAM disponible es máx(0.5, RAM instalada − RAM del SO). La demanda activa se escala con L. Si la demanda supera la memoria disponible, exceso = máx(0, demanda − disponible) y Tpaginación = exceso·2048/BWdisco·q. Se suponen dos transferencias de 1024 MB por GB de exceso y un factor q de acceso. Este umbral es una simplificación deliberada del comportamiento de memoria virtual.

TE/S = 100·d·L·(500/BWdisco)·q. Los perfiles usan HDD: 120 MB/s, q=2.5; SSD SATA: 500 MB/s, q=1; SSD NVMe: 3000 MB/s, q=0.8. Se pueden modificar los MB/s de forma independiente. Estos valores representan ejemplos hipotéticos, no especificaciones universales.

GPU, sistema operativo, energía e índice

TGPU = 100·g·L/GPUrel. El factor GPU solo afecta a la fase gráfica del escenario y no implica un modelo real de GPU. IPC relativo representa trabajo útil por ciclo y tampoco corresponde a un procesador comercial.

El perfil Windows carga 3 GB para el SO y 10% de carga de fondo. Linux carga 2 GB y 6%. El perfil personalizado carga 2 GB y 5%. Todos son supuestos editables. Con los mismos recursos reservados y la misma carga de fondo, cambiar únicamente el nombre del SO no altera el resultado.

Potencia media hipotética: 35 + 4·n·(fef/3.2)²·(TCPU/T) + 0.25·RAM + 30·GPUrel·(TGPU/T), en W. Energía (Wh)=potencia·T/3600. No simula voltaje, turbo ni un perfil físico de consumo. El índice se calcula como 100·Treferencia/T. La referencia conserva una configuración fija y se recalcula para la misma tarea. Puede cambiarse con el botón «Fijar referencia».

Interpretación de los porcentajes y alcance

La aceleración de B frente a A es S = TA/TB. El aumento de rendimiento es (S−1)·100 y la reducción del tiempo es (1−1/S)·100. Por ejemplo, S=1.5 representa 50% más rendimiento y 33.3% menos tiempo. La mayor contribución al tiempo es una pista para optimizar, no una medición de utilización de hardware.

Los escenarios tienen fracciones base que suman uno, a 1 núcleo, 3.2 GHz, IPC=1, 8 MB de caché y sin carga de fondo. Los resultados no predicen FPS, latencias de red, compatibilidad de sistemas operativos ni benchmarks de productos. Referencias: Patterson y Hennessy, capítulo 1; SPEC, metodología; Williams et al. (2009), Roofline. Este simulador no implementa el modelo Roofline completo.
